# Research-first: establish the uncertain part

Use for unfamiliar APIs, libraries, datasets, hardware or geometry. Start with the actual project instructions, source and question.

1. **Inspect:** open relevant official documentation, examples, permitted samples or exact part references. Show what supports the proposed use and what remains uncertain.
2. **Compare:** offer a few feasible approaches with tradeoffs in scope, reliability, resources and explainability. Let the student choose consequential changes.
3. **Plan a small test:** name the input, expected result, preserved condition and what the result would establish.
4. **Implement within scope:** make the chosen small slice and preserve a meaningful version.
5. **Check and decide:** record what actually happened, the limit and the next decision. Use the project's existing process record.

A documentation link is a source to inspect, not proof an integration runs. Use actual fields from a permitted sample. For hardware, distinguish exact parts and measurements from assumptions; simulation or geometry can answer a bounded question while physical fit/function still needs an appropriate test with guidance.

Ask about missing inputs rather than invent fields, pin numbers, supplier values or results. Keep private data and credentials protected under the class guidance.
